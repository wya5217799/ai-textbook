### **Data Errors**

- Data often have errors the mismatch with ground truth (missing, erroneous or extreme values)
  - e.g. missing, erroneous or extreme values
- Good ML models are robust to errors
- Consequences:
  - The training may still converge, but slower
  - Accuracy degradation, could be hard to detect
  - Deploying these models may impact the quality of the new collected data
    - e.g. positive examples generated by poor recommendation / search results

![](images/L2_Overview_of_machine___page_22_Picture_10.jpeg)


### **Types of Data Errors**

- Outliers: data values that significantly deviate from other observations
  - outliers VS under sampled rare events
- Rule violations: data values violate integrity constraints such as "Not Null" and "Must be unique" and "Non negative"
- Pattern violations: data values violate syntactic and semantic constraints such as formatting, misspelling

### **Rule-based Detection**

- Design rules to identify erroneous records
- Functional dependencies: *x→y* means a value determines a unique value *y*
  - E.g. zip code→state, EIN→company name
- Denial constraints: specified with more flexible first-order logic
  - Phone number is not empty if vendor has an EIN
  - If two captures of the same animal indicated by the same tag number, then the first one must be marked as original


### **Pattern-based Detection**

- Syntactic patterns
  - e.g. Map a column to the most prominent data type and identify values do not fit
  - eng, en, english -> English
- Semantic patterns
  - e.g. Add rules through knowledge graph
    - Values in column "Country" need have capitals, so a value "Stanford" is invalid


### **Summary**

- Types of data errors: outliers, rule violations, pattern violations
- Multiple tools exist to help data cleaning
  - Graphic interface for interactive cleaning
  - Automatically detect and fix

### **Batch Gradient Descent**

optimization objective

$$J(\theta) = \frac{1}{2N} \sum_{i=1}^{N} (y_i - f_{\theta}(x_i))^2 \qquad \min_{\theta} J(\theta)$$

Update parameters based on the gradient of the entire batch data

$$\theta_{\text{new}} \leftarrow \theta_{\text{old}} - \eta \frac{\partial J(\theta)}{\partial \theta}$$

$$\frac{\partial J(\theta)}{\partial \theta} = -\frac{1}{N} \sum_{i=1}^{N} \left( (y_i - f_{\theta}(x_i)) \frac{\partial f_{\theta}(x_i)}{\partial \theta} \right)$$

$$= -\frac{1}{N} \sum_{i=1}^{N} (y_i - f_{\theta}(x_i)) x_i$$

$$\theta_{\text{new}} = \theta_{\text{old}} + \eta \frac{1}{N} \sum_{i=1}^{N} (y_i - f_{\theta}(x_i)) x_i$$

## **Stochastic gradient descent**

➢ optimization objective

$$J^{(i)}(\theta) = \frac{1}{2} (y_i - f_{\theta}(x_i))^2 \qquad \min_{\theta} \frac{1}{N} \sum_{i} J^{(i)}(\theta)$$

➢ Update parameters based on the gradient of the entire batch data

$$\theta_{\text{new}} = \theta_{\text{old}} - \eta \frac{\partial J^{(i)}(\theta)}{\partial \theta}$$

$$\frac{\partial J^{(i)}(\theta)}{\partial \theta} = -(y_i - f_{\theta}(x_i)) \frac{\partial f_{\theta}(x_i)}{\partial \theta}$$

$$= -(y_i - f_{\theta}(x_i)) x_i$$

$$\theta_{\text{new}} = \theta_{\text{old}} + \eta (y_i - f_{\theta}(x_i)) x_i$$

- ➢ Batch gradient descent vs.
  - Faster parameter updating (advantage)
  - Uncertainty or oscillation in learning (disadvantage)

## **Mini-batch Gradient Descent**

- ➢ Combination of batch gradient descent and random gradient descent
- ➢ Divide the entire training set into mini-batches {1,2,3, ⋯ ,}

$$\theta_{\text{new}} = \theta_{\text{old}} - \eta \frac{\partial J^{(k)}(\theta)}{\partial \theta}$$

## **Loss Function of Logistic Regression (Binary)**

### Loss Function

$$\mathcal{L}(y, x, p_{\theta}) = -\delta(y = 1) \log p_{\theta}(y = 1|x) - \delta(y = 0) \log p_{\theta}(y = 0|x)$$
$$= -y \log p_{\theta}(y = 1|x) - (1 - y) \log(1 - p_{\theta}(y = 1|x))$$

Where, 
$$\delta(z) = \begin{cases} 1, & z \text{ is true} \\ 0, & \text{otherwise} \end{cases}$$

## **Gradient Logistic Regression**

➢ Logistic regression is a binary model

$$p_{\theta}(y = 1|x) = \sigma(\theta^{\mathsf{T}}x) = \frac{1}{1 + e^{-\theta^{\mathsf{T}}x}}$$

$$p_{\theta}(y = 0|x) = \frac{e^{-\theta^{\mathsf{T}}x}}{1 + e^{-\theta^{\mathsf{T}}x}}$$

![](images/L4_and_5_Gradient_Desce__page_20_Figure_4.jpeg)

➢ Cross entropy loss function

$$\mathcal{L}(y, x, p_{\theta}) = -y \log \sigma(\theta^{\mathsf{T}} x) - (1 - y) \log \left(1 - \sigma(\theta^{\mathsf{T}} x)\right)$$

➢ Gradient

$$\frac{\partial \mathcal{L}(y,x,p_{\theta})}{\partial \theta} = -y \frac{1}{\sigma(\theta^{\mathsf{T}}x)} \sigma(z) (1 - \sigma(z)) x - (1 - y) \frac{-1}{1 - \sigma(\theta^{\mathsf{T}}x)} \sigma(z) (1 - \sigma(z)) x$$
$$= (\sigma(\theta^{\mathsf{T}}x) - y) x$$

$$\theta \leftarrow \theta + \eta \big( y - \sigma(\theta^{\mathsf{T}} x) \big) x$$

$$\left(\frac{\partial \sigma(z)}{\partial z} = \sigma(z)(1 - \sigma(z))\right)$$


# **Softmax**

## **Softmax**

• Used in Multiple Classification

• Softmax calculates the probability:

# **Regression – Evaluation Metric**

## **Linear Regression – Evaluation Metric**

### ► Mean Squared Error, MSE

$$MSE = \frac{1}{n} \sum_{i=1}^{n} (y_i - \hat{y}_i)^2$$

![](images/L6_Evaluation_Indicator__page_2_Figure_4.jpeg)

### Advantages:

- MSE provides a smooth, continuous, and differentiable funct gradient descent algorithms.
- As errors decrease, gradients also decrease, aiding convergence.
- Sensitive to measurement errors, effectively reflecting the discrepancies between predicted and actual values.

### Disadvantages:

- MSE can amplify errors when the difference between true and predicted values is greater than 1, and vice versa.
- Sensitive to outliers, which can significantly impact the model's performance and reduce overall accuracy

### **Linear Regression – Evaluation Metric**

#### Root Mean Squared Error (RMSE)

$$RMSE = \sqrt{\frac{1}{n} \sum_{i=1}^{n} (y_i - \hat{y}_i)^2}$$

![](images/L6_Evaluation_Indicator__page_3_Figure_4.jpeg)

#### Advantages:

- •RMSE quantifies the deviation between predicted and true values, with lower values indicating higher prediction accuracy.
- Easy to understand and calculate.

#### > Disadvantages:

- •RMSE doesn't account for the variability inherent in the target variable, potentially misrepresenting the model's performance.
- •Sensitive to outliers, leading to less stable evaluation results.

### **Linear Regression – Evaluation Metric**

#### Mean Absolute Error (MAE)

$$MAE = \frac{1}{n} \sum_{i=1}^{n} |y_i - \hat{y}_i|$$

#### > Advantages:

- MAE is less sensitive to outliers as it calculates the absolute value of errors.
- Intuitive and easy to understand, measuring errors in the same units as the original data.
- Usable in some optimization algorithms despite not being differentiable everywhere.

#### > Disadvantages:

- MAE treats all errors equally, disregarding the importance of individual data points.
- Not continuously differentiable, which can complicate its use in certain optimization algorithms.
- For small loss values, gradients can be relatively large, hindering convergence and learning.

$$R2 = \frac{SSR}{SST} = \frac{\sum_{i=1}^{n}(\hat{y_i} - \bar{y})^2}{\sum_{i=1}^{n}(y_i - \bar{y})^2}$$

$$SST = \sum_{i=1}^{i=n} (y_i - \bar{y})^2$$

# **F1 Score**

The tradeoff between accuracy and recall

$$\hat{y} = \begin{cases} 1, & p_{\theta}(y = 1|x) > h \\ 0, & \text{otherwise} \end{cases}$$

- F1 Score
  - The higher the threshold, the higher the precision rate and the lower the recall rate
    - extreme case:threshold=0.99
  - The lower the threshold, the lower the precision and the higher the recall rate
    - extreme case:threshold =0

$$F1 = \frac{2 \times Precision \times Recall}{Precision + Recall}$$

- **F1 = 1**: Perfect model (Precision=1, Recall=1).
- **F1 = 0**: Complete failure (Precision=0 or Recall=0).
- **Practical Scenarios**:
  - **High Precision, Low Recall**: Predictions are accurate but miss many positives.
  - **High Recall, Low Precision**: Captures most positives but with many false alarms.
  - **Maximizing F1**: Optimal balance between Precision and Recall.

#### **DBSCAN**

- Density-Based Spatial Clustering of Applications with Noise
  - Core object: If the density of a point reaches the threshold set by the
    algorithm, it is the core point.(i.e., the number of points in r neighborhood is
    not less than minPts)
  - ε- Neighborhood distance threshold: set radius r
  - **Direct density reachable:** If a point p is in the r neighborhood of point q, and q is the core point, then the direct density of p-q is reachable.
  - **Density can be reached:** if there is a sequence of points q0, q1,... qk is directly density-accessible for any qi--->qi-1, It is said that the density is reachable from q0 to qk, which is actually the "propagation" of direct density reachable.


#### **DBSCAN algorithm**

## ➢ Basic concepts:

- **Density connected:** If starting from a core point p, point q and point k are both density-reachable, then point q and point k are density-connected.
- **Boundary point:** A non-core point belonging to a class that cannot be developed
- **Direct density reachable:** If a point p is in the r neighborhood of point q, and q is the core point, then the direct density of P-Q is reachable.
- **Noise points:** Points that do not belong to any of the class clusters are density-inaccessible from any of the core points

![](images/L8_Clustering__page_7_Picture_0.jpeg)

- ➢ Basic concepts:
  - A: Core object
  - B,C: boundary point
  - N: outlier

![](images/L8_Clustering__page_7_Picture_5.jpeg)

#### **Pseudocode**

```
DBSCAN(DB, distFunc, eps, minPts) {
 C := 0 /* Cluster counter */
 for each point P in database DB {
 if label(P) ≠ undefined then continue /* Previously processed in inner loop */
 Neighbors N := RangeQuery(DB, distFunc, P, eps) /* Find neighbors */
 if |N| < minPts then { /* Density check */
 label(P) := Noise /* Label as Noise */
 continue
 }
 C := C + 1 /* next cluster label */
 label(P) := C /* Label initial point */
 SeedSet S := N \ {P} /* Neighbors to expand */
 for each point Q in S { /* Process every seed point Q */
 if label(Q) = Noise then label(Q) := C /* Change Noise to border point */
 if label(Q) ≠ undefined then continue /* Previously processed (e.g., border point) */
 label(Q) := C /* Label neighbor */
 Neighbors N := RangeQuery(DB, distFunc, Q, eps) /* Find neighbors */
 if |N| ≥ minPtsthen { /* Density check (if Q is a core point) */
 S := S ∪ N /* Add new neighbors to seed set */
 }
 }
 }
}
```

```
RangeQuery(DB, distFunc, Q, eps) {
 Neighbors N := empty list
 for each point P in database DB { /* Scan all points in the database */
 if distFunc(Q, P) ≤ eps then { /* Compute distance and check epsilon */
 N := N ∪ {P} /* Add to result */
 }
 }
 return N
}
```
